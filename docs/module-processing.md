## 目标

把「加工」这段成本变成可追溯的新批次，并把损耗只摊量不减价（D5）与全损耗损失（G2/D26/D35）在实现层固定下来。

## 范围与页面

- **功能域（D44）**：加工单 B。
- **页面**：4 加工单。
- **实体**：B 加工单（单号/引用批次/辅料/加工厂/加工费/运杂费/损耗量/可售量/归属单/状态）、损失记录（来源 B 单/损失金额/原因/归属单）。
- **不做**：包工包料走 A 单（F2b）；损耗事后修改（F3 验收时一次填入，事后不改）。

## 依赖

- 上游：platform（权限/审批/取号）、masterdata（加工厂/商品）、inventory（引用批次、产出批次、流水）。
- 下游：sales（引用 B 单产出批次）、settlement（损失归属进 C 单）。

## 开放项

- 契约第一批 §11-4：**损耗量精度** —— 拟定保留 2 位小数。开工前拍板并追加 decisions.md。

## 验收标准

- **至少一条材料投入明细**，否则不允许提交（F2b）；可链式引用其他 B 单产出的批次（非主线，F2）。
- 只能引用本公司批次（D22）。
- 产出新批次：`批次单价 = (引用材料成本 + 辅料 + 加工费 + 运杂费) ÷ 可售量`；可售量 = 投入量 − 损耗量（D5）。
- 可售量 > 0 才生成产出批次；可售量 = 0 走「全损耗」二次确认：B 单可提交、不生成产出批次、材料 + 加工费全额记损失并留痕，投入批次库存照常扣减（G2）。
- 「归属单」（E 或 N，选填）可挂；全损耗时提示挂单（D35）。
- B 单费用行一律 ≥ 0（D39）。
- 取消：无下游引用可取消，流水同事务回滚（D21）。

- 全损耗**不能**除零：先判可售量为 0 的分支，再算批次单价（G2）。

- `ProcessingOrderUpdateInputSchema` 当前仍允许 `fees: []`；运行时 usecase 已收紧，
  但 OpenAPI/契约 schema 仍需主线后续同步为 `.min(1)`。
