# 模块：sales（销售、收款与客户退货）

## 目标

把货卖出去、把钱收回来、把错了的销售单退回来：E 单负责成交与改价审批，收款记录 + 在线支付负责钱，R 客户退货负责逆向。

## 范围与页面

- **功能域（D44）**：销售单 E、客户退货 R。
- **页面**：5 销售单 E（列表/详情/录入 + 内嵌「收款记录」块）；R 作为冲正单据类型（页面 8 的一部分）。
- **实体**：E 销售单（单号/客户/商品明细/费用明细/状态/经手人）、收款记录（方向/金额/方式/时间/关联冲正单）、R 退货单（类型/退款方式/关联原 E 单/关联原 C 单）。
- **不做**：独立支付页/支付状态字段（D24）；退款写成 E 单负数费用行（禁止，D40）；记账模块（D11）。

## 依赖

- 上游：platform（权限/取号/审批/状态机）、masterdata（客户/商品）、inventory（批次引用、退货入库流水）。
- 下游：settlement（E 单完成生成 C 单草稿；退款触发毛利/提成重算）。

## 开放项

- 契约第一批 §11-1：**商品明细「批次 id」是否必填** —— 拟定必填（E/B 必须引用批次）。开工前拍板并追加 decisions.md。
- 契约第一批 §11-2：**收款记录是否支持部分退款** —— 拟定支持（负数行可多次）。开工前拍板并追加 decisions.md。

## 验收标准

- 只能引用本公司批次（D22）；选批次弹窗只显示可用量（D38）。
- 改价下限 = **该行加权平均批次成本**，按行校验、按行审批留痕；审批中该行锁定不可改；下限默认 = 成本价、租户可配（D20/D4.1）。
- 费用行一律 ≥ 0，跳过下限校验（D32/D39）；折扣/返利走售价字段或收款记录块，不走负费用行。
- 收款记录内嵌 E 单详情页：在线支付回调与线下转账人工标记同块；块内余额 = 收款合计 − 退款合计（D24/D34）。
- 客户在线支付模式 A：企业自配微信/支付宝商户号，钱直接进企业账户，平台只传指令 + 到账回调（D11）。
- R 客户退货两类型：退货退款（有入库流水）/ 仅退款（无实物流水）；退款方式：原路退款 / 冲抵应收（F4）。
- 仅退款两型：①纠收款退款（不重算毛利提成）②减成交额退款（按 C 单快照比例重算毛利提成并留痕）（D40）。
- R 多岗可录 + 录入需审批（老板/经理/财务，D47）；退款只走收款记录负数行。
- E 单单头三态；「已完成」自动生成 C 单草稿（D19）；已完成/已结算不提供取消，错账走 R（D21）。
