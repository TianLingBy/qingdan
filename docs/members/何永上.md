## 工作流程（团队统一，2026-11-05 起）

1. 任务只在 GitHub issue 领；进度只认 issue / PR 状态，本地笔记不算。
2. 分支：`feat/web-<要点>`（例如 `feat/web-design-tokens`、`feat/web-component-table`）。
3. PR 描述必须包含 `- Blocked by: 无` 和 `- Blocks: 无`（没有阻塞也写「无」，否则 CI 的 fields 检查会红）。
4. 合并前本地跑绿：`pnpm -r build`、`pnpm -r test`、`pwsh -NoProfile -File tests\run.ps1`。
5. **提交不直接推 main**，一律 PR；CI 七项全绿后由负责人合并。

## 验收标准

- 组件有测试（`apps/web/src/components/**/*.test.ts`），有用法示例或 Story 级说明。
- 金额组件必须支持「无看价权限时展示占位符」这一态（后端按 D79 返回 `null`）。
- 表单一律带校验态、禁用态、错误态；表格带空态、加载态、分页。
- 视觉改动附截图；不加新依赖除非说明理由（现有已够用：TanStack Query、Zod、Vite、React 19）。

## 第一周建议顺序

1. **设计 tokens + 布局骨架**：颜色、间距、字号、圆角先进样式层，后面所有组件引用它。
2. **基础组件**：按钮、输入、表格、分页、金额、状态标签、空态/错误态。
3. **业务组件**：单据头、行明细表、流转时间线（这三样单据 6 页高度复用，优先级最高）。
4. 配合皓妍的设计稿做视觉走查，逐页给业务实现者确认。
