## 工作流程

1. 任务与进度只以 GitHub issue / PR 为准；优先级和归属有疑惑时直接向用户确认。
2. 分支使用 `feat/<模块>-<要点>`、`fix/<模块>-<要点>` 或 `docs/<要点>`。
3. 跨模块调用只走 `platform/services/registry.ts` 端口，不直接读取其他模块的数据表。
4. 改契约时必须运行 `pnpm openapi` 并提交 `docs/api/openapi.yaml`；改其他模块前先取得负责人明确同意。
5. 合并前要求 typecheck、ESLint、全仓 build/test、`pwsh -NoProfile -File tests\run.ps1` 和 CI 七项全绿。

## 验收标准

- 接真实接口，不伪造业务数据；空态、加载态、错误态齐全。
- 金额与数量使用 decimal 字符串，不使用 JavaScript 浮点参与业务计算。
- 金额字段遵守看价权限；无权限显示占位，不返回或展示 0 作为替代。
- 写操作遵守强 `If-Match` 版本语义；并发冲突必须有可操作提示。
- 关键后端链路必须有数据库级测试；前端页面必须有自动化测试，并在需要时完成真实浏览器验收。
