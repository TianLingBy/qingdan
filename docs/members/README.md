# 成员档案（开工前必须先落盘）

> **一句话规则**：**先确认身份、再领任务、必须落盘**。只在群里说「我来做 X」不算数，档案没提交进仓库就等于没开工。

## 为什么要有这个目录

轻单是多人 + 多 AI 并行开发的仓库，最怕两件事：**两个人以为自己在做同一块**、**做完发现做的不是约定的那一块**。所以每个人开工前必须把自己的身份、模块、写范围和日期写进仓库，成为可追溯的事实，不依赖聊天记录。

## 规则

1. **一人一份**：`docs/members/<姓名>.md`，文件名用**中文真实姓名**（如 `温汇敏.md`），不缩写、不用拼音、不合并到一个公共文件。
2. **先落盘，后开工**：档案 PR 未合并前，**不允许**提交任何代码或业务文档改动。
3. **档案必填字段**（缺一项视为未完成）：姓名、交付模块、代码模块、分支名、**写范围（含明确不能改的部分）**、负责人/评审人、接手日期、环境自检结果（`install-hooks.ps1` + `tests\run.ps1` 的真实输出行）。
4. **只改自己的档案**：不得修改他人档案；分工变动（换模块、扩范围）时改自己的档案并在 PR 描述里写明原因。
5. **与边界文档冲突时**：以 `docs/ROLES-AND-BOUNDARIES.md` 的红线为准，先改档案再动手。
6. **模块检查点同步登记**：在 `docs/module-<模块>.md` 顶部「负责人」一行写上自己姓名 + 接手日期（同一 PR 内完成）。
7. **档案不写密码/密钥/个人隐私**，只写工作所需的身份与范围信息。

## 开工五步（照抄即可）

```text
① 读 docs/ONBOARDING.md → 跑 pwsh -NoProfile -File bootstrap.ps1 -Module <模块>
   成功标志：BOOTSTRAP-OK（装好 hook、全量测试通过、建好自己分支）
② 复制 docs/members/_template.md → docs/members/<姓名>.md，逐项填满
③ 在 docs/module-<模块>.md 顶部登记「负责人：<姓名>｜接手日期：YYYY-MM-DD」
④ 提交 PR（标题：chore(members): 登记 <姓名> 的成员档案）
⑤ 档案合并后才开始领任务、写代码；领任务在 GitHub Issues 对应模块 label 下认领
```
