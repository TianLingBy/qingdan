## 0. 范围与边界

**本批覆盖**：
- 操作日志（平台 / 员工 / AI 全量审计）
- API Token（机器身份与授权）
- 通用 API 约定（错误体 / 分页 / 幂等 / 并发 / 预检 / 限流 / OpenAPI）
- CLI 与 MCP 的映射规则
- 平台运营后台的审计要求（手动计费、企业停用等）

**本批不覆盖**：具体业务单据字段（见第一 / 第二批契约）；Webhook 事件订阅（二期评估）；订阅费在线支付（D1 不做）。

## 1. 操作日志（audit_log）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | uuid | ✅ | 日志主键，全局唯一 |
| 时间 | datetime | ✅ | 服务端时间（UTC 存储，按租户时区展示） |
| 租户 id | uuid | ✅ | 平台侧操作可空（平台级） |
| 公司 id | uuid | 选填 | 单据/档案类操作必填 |
| 操作者类型 | enum | ✅ | `platform` 平台开发者 / `employee` 员工 / `ai` AI / `system` 系统任务 |
| 操作者 id | uuid | ✅ | 员工 id 或平台账号 id；`system` 用固定标识 |
| 凭证 id | uuid | 选填 | AI 调用时为 token id；人类会话可记 session id |
| 来源 | enum | ✅ | `web` / `cli` / `api` / `mcp` / `job` |
| 动作 | text | ✅ | `功能域.动作`，如 `sales.create`、`settlement.confirm` |
| 对象类型 | text | ✅ | 单据/档案/权限/Token/日志 等 |
| 对象 id | uuid | 选填 | 目标实体主键 |
| 变更摘要 | json | 选填 | 变更前/后关键字段；金额与成本字段按「看价」权限脱敏（D27） |
| 结果 | enum | ✅ | `success` / `fail` |
| 错误码 | text | 选填 | 失败时填 |
| 请求 id | text | ✅ | 透传 `X-Request-Id`，用于全链路关联 |
| IP / UA | text | 选填 | 来源设备信息 |
| 原因 | text | 条件必填 | 危险动作（删除 / 冲正 / 成本更正 / 结算确认 / 权限变更）与 AI 写操作必填 |
| 业务事务 id | text | 选填 | 与业务写入关联，便于对账 |

**规则**：
- **只追加**：不提供更新 / 删除接口；平台侧保留独立副本，租户删除任何数据都不影响日志。
- **失败也记**：审计写入独立追加，不随业务事务回滚；业务失败同样落一条 `fail`。
- **口径一致**：金额类字段按 D27「看价」权限脱敏；日志本身的查看也记日志。
- **覆盖清单**（默认，见 §5 开放项 1）：登录 / 登出 / 失败登录、权限与岗位变更、个人权限覆盖、API Token 增删改、全部写操作、导出、查看敏感金额、查看操作日志、AI 全量调用、平台运营后台全部操作。

## 2. API Token（机器身份）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | uuid | ✅ | |
| 租户 id | uuid | ✅ | |
| 绑定员工 id | uuid | ✅ | 含专门创建的服务账号员工 |
| 名称 | text | ✅ | 便于识别人 / Agent / 系统 |
| scope | json | ✅ | 功能域 × 动作子集（8 动作枚举见第一批 §1.2） |
| 有效期 | datetime | 选填 | 到期自动失效 |
| IP 白名单 | text[] | 选填 | 空 = 不限制 |
| 最后使用时间 | datetime | 选填 | 每次调用更新（异步，允许延迟） |
| 状态 | enum | ✅ | `active` / `revoked` / `expired` |
| 创建人 | uuid | ✅ | 员工 id |
| 撤销时间 | datetime | 选填 | |

**规则**：
- 明文只在创建时返回一次，服务端只存哈希；可随时撤销。
- **权限 = 绑定员工权限**（公司集合 + 岗位并集 + 个人覆盖），再取 scope 交集；**不能超越人**，不提供租户级「上帝 token」（见 §5 开放项 4）。
- 写操作必须携带 `reason`（意图说明），进操作日志。
- 每 token 限流；超限返回 429 与 `Retry-After`。

## 3. 通用 API 约定

| 项 | 约定 |
|---|---|
| 版本 | `/api/v1`（破坏性变更才升版本） |
| 认证 | 人类：会话 Cookie；机器：`Authorization: Bearer <token>` |
| 错误体 | `{ "code": "...", "message": "...", "details": {...}, "requestId": "..." }`，HTTP 状态码与 `code` 同时给 |
| 分页 | 游标：`?cursor=&limit=`，`limit` 默认 50、最大 200；返回 `nextCursor` |
| 幂等 | 写接口支持 `Idempotency-Key`，24h 内重复请求返回首次结果 |
| 并发 | 单据/批次写接口要求 `If-Match: <version>`，冲突返回 409 |
| 预检 | 全部写接口支持 `dryRun=true`：只校验不落库，返回将要发生的变更与错误 |
| 请求 id | 客户端可传 `X-Request-Id`，服务端透传并回写；缺省则生成 |
| 时间 | ISO 8601 带时区；金额 decimal 字符串（避免浮点误差） |
| 文档 | `GET /api/v1/openapi.json`（OpenAPI 3.1，唯一接口真源） |
| 审计 | 每个写接口、每次 AI 调用都必须产生操作日志（§1） |

## 4. CLI 与 MCP 映射

- **CLI**：`qingdan <功能域> <动作> [--json] [--dry-run] [--reason "..."]`；退出码约定 `0` 成功 / `2` 用法错误 / `3` 无权限 / `4` 校验失败 / `5` 并发冲突。
- **MCP Server**：每个工具与一个 REST 接口一对一，工具描述里声明所需 scope 与是否需要 `reason` / 审批；Agent 通过 MCP 看到的权限与 Web 完全一致。
- **共同约束**：CLI 与 MCP 都是薄客户端，**不得绕过服务端权限与审计**；同一动作三种入口的行为、错误码、日志字段必须一致。

## 5. 🟡 开放项（平台开工前必须确认并冻结本批）

| # | 项 | 拟定默认 | 待确认 |
|---|---|---|---|
| 1 | 日志覆盖哪些「读」 | 写操作全量 + 敏感读（导出 / 看金额 / 看日志）记录；普通列表与详情查询不记 | 是否连普通查询也要记 |
| 2 | 日志保留期 | 云端 ≥ 180 天，随本地只读备份同步；到期归档不物理删除 | 180 天是否够 / 是否永久 |
| 3 | AI 危险动作边界 | 删除 / 冲正 / 成本更正 / 结算确认 / 权限变更**默认禁止 AI 执行**；租户可开「允许 AI 走审批」，开启后仍走审批并带 reason | 是否允许 AI 直接确认结算或冲正 |
| 4 | API Token 粒度 | 绑定到员工（含服务账号员工），继承公司集合与岗位并集 | 是否需要租户级集成 token / OAuth 应用 |
