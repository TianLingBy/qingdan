## 有意差异（请在 PR 里裁定，不是漏做）

1. **表头不可排序**：稿子的单号 / 金额 / 日期带 ↕，但 `InternalTradeOrderListQuerySchema`
   只有 `cursor / limit` 与四个筛选字段，**没有 `sort` / `order`**（D95 的页码 + 白名单排序
   只在 A / E 试点）。画一个点了没反应的箭头比不画更糟。
2. **不画条数、不画合计、不画页码**：N 单走游标分页，响应没有 `total`，也没有分组计数。
   「这一批 5 条」写成「共 5 条」已经是本批口径，再加一个「合计 ¥…」会被读成
   「全部筛选结果的合计」。与 B 页同一口径（A / E 是页码模式，有 `total` 才给合计）。
3. **「对接公司」写「发出 → 接收」**：稿子是单公司视角，只写对方名字。本仓一张 N 单同时属于
   两家公司，看的人可能是任一边，只写一个名字会让人分不清是发出去还是收进来。
4. **`全部经手人` 下拉没画**：列表契约没有 `handlerId`，接了也筛不动。
5. **发出 / 接收公司两个下拉删掉**：稿子工具栏里没有它们（见 PR「需要拍板」）。
   **后果**：多公司账号在这页会看到所有公司之间往来的 N 单，只能靠「对接公司」列眼看。
6. **外壳（左侧栏 / 顶栏）没动**；7. **按钮圆角 999px**；8. **状态徽标比稿子大 1–2px** ——
   三条都属全站口径，见采购单 A 的记录。

## 顺手修的层叠问题（`app-v30.css`）

`.cell-sub{display:block}`（`app-v013.css` L536，那时当副标题用）没被 v30 的覆盖规则改回来，
于是「商品 等 2 种」在单元格里另起一行 —— 同一张表里有的行 50px、有的行 68px。
补 `display:inline`：`app-v30.css` 那条规则的 `margin-left:4px` 本来就是按行内写的。
影响面：N 页列表、盘点单（`StocktakesPanel`）、付款申请（`PaymentRequestPanel`）三处后缀小字，
都是「同一行里的次要说明」，本来就该是行内。

## 截图里一个与版式无关的现象

`internal-after-detail.png` 的「批次」徽标显示短 id（`01900000…`），不是批次号：
这张单引用的批次在批次列表里查不到（联调种子把同一批次在另一张单的到货确认里转司了，D31），
前端按既有规则退回 id 前 8 位。真库上批次可见时显示批次号；与列表版式无关。
