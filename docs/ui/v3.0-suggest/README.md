# 开单草档的建档防重联想（`SuggestHint`）

`#431` 必做点 7（原 #303 并入）/ D99。三处「开单现场建档」的名称框接上 `components/SuggestHint.tsx`：
销售 E 的「+ 新建客户」、采购 A 的「+ 新建供应商」、加工 B 的「+ 新建加工厂」。

组件本身与请求层（`components/masterdata-suggest-api.ts`）早就在 main，本单只做接线，
不写第二份请求层、不引下拉库。

## 交互口径

1. 名称打进 **2 个字**（契约下限）才发请求；`companyId` 取当前单据公司（漏传 422）。
2. 命中相似档案 → 名称框所在草档的最后一行出现「已有相似档案，点一下直接用，别新建重复的」+ 候选按钮
   （名称 · 理由 · 相似度）。
3. 点候选 = **不建档**：草档收起、清空，供应商/客户/加工厂下拉直接指向这条已有档案，
   页面顶部给一条琥珀色提示「已选中已有客户「王记五金」，这次不再新建档案」。
   这一条很关键——`customerId` 与 `customerDraft` 同时提交服务端会 422，所以选中即清草档。
4. 没候选 / 没权限 / 请求失败 → **什么都不渲染**，不占位、不挡保存（suggest 是辅助不是必经步骤）。

## 两个值得记下来的坑

- **相似度是 bigram Dice，短名才容易过阈值**。同一个供应商，打 `鸿达` 反而没有候选
  （query 1 个 bigram vs 名称 6 个，Dice≈0.29 低于阈值），打 `东莞鸿` 才有（0.5）。
  这是服务端 `name-similarity.ts` 的口径，不是前端 bug —— 前端照契约原样展示「部分相似 · 57%」，
  不在这边偷偷放宽。
- **商品没有对应的名称输入框**，所以「商品联想」这一路没有接线点：商品在采购 / 加工 / 销售 /
  内贸四张单里一律从下拉选已有档案（引用批次是开单硬门槛，D22），不做现场建档。
  `product.suggest` 端点仍在，等真出现「现场建商品」的需求再接。
