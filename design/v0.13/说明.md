> 基准：`v0.12`（结构性去重版）。**信息架构、页面内容、视觉表现保持不变**，本次只做一件事：把空态从「半成品」补成 issue #145 要求的样子。
> v0.12 及更早目录完整保留，未做任何改动。纯静态，双击任意 `.html` 即可打开。

## 〇、v0.13 做了什么（空态 / 加载态 / 错误态）

v0.12 的空态是简陋路径：`∅` 字符图标 + 全站同一句「筛下来一条都没有」，而且漂亮的等距插图（`ART.empty`）和按钮样式（`.st-btn`）早就写好了，却没接上。v0.13 把这条链补齐：

| 改进 | v0.12 | v0.13 |
|---|---|---|
| 插图 | `∅` 字符（44px 小方块） | `ART.empty` 等距三纸堆叠插图（96px，与单据详情的 `.st-box` 同一视觉语言） |
| 文案 | 全站一句「筛下来一条都没有」 | **按页面（`data-nav`）专属**：19 个带表格的列表页各有标题 + 说明，口径对齐真源（冲正 = R/S/I、库存 = 员工归属、结算 = 一单一成本收口…） |
| 主操作 | 无按钮 | 主按钮（黑色 primary）+ 视需要的次按钮（库存流水 →「查看库存」、报表 →「查看单据」）；点击走全局 `#` 拦截弹「演示稿」轻提示 |
| 分页条 | 空态下仍显示「共 12 条 / 12 页」 | 空态时同步隐藏 |
| 亮色模式 | — | 插图颜色随 `--accent-light` 变量自动切换，与 `.st-ico` 同源 |

**加载态 / 错误态（本轮一并补齐）**：列表页在 `?state=loading` 时出骨架屏（复用全局 shimmer，5 行长短交替）；`?state=error` 时出错误卡（`ART.error` 插图 + 危险色 + 「重试」按钮）。错误文案全站统一——错误是系统级事件，不按页面分文案；点「重试」去掉 state 参数回到正常列表，正好演示「重试成功」。`单据详情.html` 自带的 `data-state` 四态不受影响，两套机制互不叠加。

**没改的**：触发方式仍是 `?state=`（与 `?mode=` 可共存）；`单据详情.html` 的四态结构（`data-state` + `.st-tr`）不动；工作台没有主表格，不在覆盖范围。

**口径来源**：各页空态文案按 `PRODUCT.md` / `docs/api/openapi.yaml` 的业务口径写（冲正不直接改原单、库存按员工归属、一期不发验证码等）；无看价权限的占位符统一用真源的 `—`（报表页空态说明里已体现）。

## 一、v0.12 做了什么（历史，原样保留）

### 为什么必须做这一版

v0.7 → v0.11 的每一次改版都是**再加一层 CSS / JS**，到 v0.11 已经出现明显债务：

| 现象 | v0.11 实况 |
|---|---|
| 样式层叠加 | 8 个 CSS 按固定顺序串联：`tokens → fonts → 页面内联 → components → page → ui → visual → polish → round`，后层不断覆盖前层 |
| 同一组件写多遍 | `.sidebar`、`.card`、`.btn`、`.st`、`.pager` 各在 3–5 个文件里重复定义；`round.css` 用了 15 个 `!important` 才能压住前面的圆角 |
| 页面各自复制 | **13 个页面的内联 `<style>` 逐字相同**（3.9 KB/页 ≈ 51 KB），另有 **8 个页面挂着空的 `<style></style>`**；22 页各写一份 sidebar / topbar / foot 骨架 |
| 主题系统打架 | `ui.js` 写着 `ONLY_TWO_MODES` 并 `removeAttribute('data-theme')`（亮/暗两套）；`motion.js` 却仍在创建四套配色切换器、读 `?theme=moss/mist/bronze/paper`，而 `ui.css` 又用 `.qd-switch{display:none!important}` 把它藏掉 —— 整套是死代码 |
| 链接转场重复 | `motion.setupTransitions()` 与 `ui.bindNav()` 同时拦截所有 `<a>` 并各自 `preventDefault` + 定时跳转 |
| 文档散落 | 4 份「说明-vX.md」+ `review-logic.md` + `review-visual.md` + 55 KB 的 `审查报告.html`，内容互相重叠，且主说明还在教用户切已废弃的四套配色 |
| 引用顺序不一 | 每页 head 挂 11 个资源，顺序在页面间不一致；`审查报告.html` 把 `tokens.css` 引了两遍 |

## 二、v0.12 具体改动（历史）

### 1. 样式层 8 → 2

| 文件 | 职责 |
|---|---|
| `tokens.css` | **只放变量**：暗色 `:root` + `html[data-mode="light"]` + 尺度/动效/字体。删掉已废弃的 `mist / bronze / paper` 三套主题块，以及零引用的兼容别名（`--gold*`、`--w-*`、`--g06…`） |
| `app.css` | **只放规则**：把 8 层 CSS 按真实加载顺序做「声明级合并」——同一选择器只保留最终生效的声明，覆盖链与补丁式 `!important` 随之消失 |

合并由脚本模拟浏览器级联完成（后声明覆盖先声明，`!important` 不被普通声明覆盖），所以结果与 v0.11 逐属性等价，而不是凭感觉重写。原来散在 `ui.css` / `polish.css` / `visual.css` / `round.css` 四处的亮色覆盖，现在集中在 `tokens.css` 一个块里。

v0.12 还逐条核对并删掉了 **23 条零引用死规则**：废弃的四套配色切换器 `.qd-switch`（含 `display:none!important` 隐藏补丁）、光晕 `.qd-aura` / `.qd-field` / `.qd-pointer`、旧链接转场遮罩 `.qd-veil` 及其 `qd-enter` / `qd-leave` 状态。内页转场完全由 `html[data-trans] .main` 的动画驱动；登录页原本加了 `qd-leave` 却没有遮罩元素，只剩 190ms 空等，现改为等卡片确认动画结束后直接跳转。剩余 `!important` 都是有实际作用的覆盖（亮色主题、圆角规范、`prefers-reduced-motion`、`[hidden]`），不再是「后层压前层」的补丁链。

`fonts.css` 里两个指向同一字体的 `@import`（jsDelivr + unpkg）合并为一个。

### 2. 脚本层 3 → 2

| 文件 | 职责 |
|---|---|
| `app.js` | 合并 `motion.js` + `nav.js` + `ui.js` 的**全部活跃功能**：外观（亮暗 / 转场四选一，字号固定 18px）、壳层注入、导航分组折叠、状态机、入场、图表路径与 tooltip、等距空态插图、排序、分页、空态、抽屉、轻提示 |
| `login.js` | 从登录页内联抽出的粒子引擎 + 表单（仅一页使用，不进全站包） |

删除的死代码：四套配色 `THEMES` / `setupTheme()` / `qd-switch` / `?theme=` 引导脚本、指针光晕 `setupAura()`、以及重复的 `setupTransitions()`（链接转场只保留 `bindNav` 一处）。

**主题系统现在只有一套**：`data-mode="dark | light"`，由 `app.js` 同步立即设置（无换肤闪烁），优先读 `?mode=` → `localStorage('qd-mode')` → 系统偏好。`?fs=` / `?trans=` 同理。

### 3. 页面去重

17 个标准列表页现在是这个结构（以 `客户.html` 为例）：

```html
<link rel="stylesheet" href="tokens.css">
<link rel="stylesheet" href="app.css">
<script src="app.js"></script>
...
<body data-nav="customers" data-crumb="主数据 / 客户">
  <div class="wrap"> …本页内容… </div>
</body>
```

- 13 页重复的内联样式、8 页空 `<style>` 全部删除；
- sidebar / topbar / snapshot / foot 由 `app.js` 统一注入，页面只用 `data-nav` / `data-crumb` 两个属性提供差异；
- 顺带修掉了原来「有的页有快照条、有的页空着」的不一致，现在所有标准内页快照条一致；
- head 从 11 个引用降到 **3 个**；
- 保留页面真正独有的样式：工作台的 hero / KPI / 入口网格，单据详情的 A4 打印版式，以及审查报告、整站预览两个独立页。

`单据.html` 简化为纯跳转页；`单据详情.html` 保留 `.shell` 独立版式（自带打印样式，不套用列表页壳层）。

### 4. 文档与资产

- 6 份 md + 1 份 html 审查记录 → **一份 `说明.md`**；
- 删除 `配色对比.html`（四套配色已废弃）、`亮暗对照.html`（亮暗已由右下角设置坞实时切换）、根目录散落的 `客户.png`；
- 保留 `审查报告.html`、`整站预览.html`、`业务全流程图.html`、`API与集成.html`（均在导航 IA 内或是有效审阅产物）。`审查报告.html` 仍保留「v0.11」标题——它记录的是 v0.11 的 IA 审阅结论，属于历史归档，不是当前版本的说明。

### 5. 顺带修掉的遗留问题

| 问题 | 处理 |
|---|---|
| `审查报告.html` 两张宽表被列表页 `tbody td{white-space:nowrap}` 撑到 1295px，整页横向溢出 160px（v0.11 就有） | 局部覆盖为 `white-space:normal; overflow-wrap:anywhere`，长 `code` 允许换行，溢出归零 |
| `预览/` 里 9 张从 v0.11 复制的旧图，含已废弃的四套配色对照、圆润版对照 | 清空后重新渲染 **10 张 v0.12 实测截图**（暗/亮工作台、客户、库存、报表、单据详情、采购单、登录、审查报告、整站预览） |
| 版本号散落且不一致（登录页 `v0.11`、整站预览 `v0.11`、单据详情注释 `v0.8`） | 统一为 `v0.12`；`app.js` 注入的页脚本来就是 v0.12 |
| `login.js` 仍监听已废弃的 `qd-theme-change`（四套配色事件），永远不会被触发 | 删除；切换亮暗时 `modeFab` 重载页面，粒子引擎本就会重新初始化 |
| 登录页右下角「切换亮色」 | **保留**：它用的是 `data-mode` / `qd-mode`，与全站一致，不是死代码 |

## 三、文件结构

```
v0.12/
├── tokens.css     设计令牌（唯一变量真源，亮/暗两套）
├── app.css        应用样式（唯一规则真源）
├── app.js         全站脚本（壳层 + 导航 + 外观 + 交互）
├── login.css      登录封面专用样式
├── login.js       登录粒子引擎与表单
├── 工作台.html 等 26 个 HTML（含 4 个独立版式页）
├── 审查报告.html / 整站预览.html   独立审阅页
├── 说明.md
└── 预览/
```

内页加载顺序：`tokens.css` → `app.css` → `app.js`（同步置于 head，立即应用外观，避免闪烁）。
登录页独立：`tokens.css` → `login.css` → `login.js`（封面与内页是两套版式，互不污染）。

## 四、怎么用

| 想做的事 | 操作 |
|---|---|
| 切亮 / 暗 | 右下角 `◐` 设置坞，或 `?mode=light` |
| 字号 | 固定 18px，设置坞不再提供字号调节 |
| 换转场 | 设置坞「淡 / 滑 / 缩 / 擦」，或 `?trans=fade\|slide\|scale\|wipe` |
| 看空态 | `?state=empty`：插图 + 该页专属文案 + 主操作按钮，分页条自动隐藏（与 `?mode=` 可共存） |
| 看加载态 | `?state=loading`：全部列表页出骨架屏（shimmer 5 行）；`单据详情.html` 走自带 `data-state` 骨架行 |
| 看错误态 | `?state=error`：全部列表页出错误卡（`ART.error` 插图 + 「重试」按钮，点重试回到正常列表 = 重试成功的演示） |
| 改配色 | 只编辑 `tokens.css` 的 `:root` / `[data-mode="light"]` 两个块 |
| 改组件 | 只编辑 `app.css`，不再需要判断「该改 8 层里的哪一层」 |
| 改空态文案 | 只编辑 `app.js` 的 `EMPTY_BY_PAGE` 映射表（按 `data-nav` 一页一条） |
