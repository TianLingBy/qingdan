# UI 结构逻辑审查 · logic-reviewer

## 结论
v0.11 的**页头结构（eyebrow + h1 + sub + 右上主操作）已经成立**，25 页里 19 页第一眼能看出「这是什么、该干什么」，IA 22 页也与 `routes.ts` 完全对齐。
但共享层只覆盖了 10 个页面，**另外 13 个列表页各自内联了一份旧 CSS 副本**，导致亮暗/字号/空态/分页/排序/抽屉在这些页整体失效——这是本次最严重的问题，不是视觉问题而是「同一产品两套系统」。
字段层面问题最密集：**清单页缺真源的关键列（操作、来源单、净毛利、损耗、在途量、锁定单价），术语用「对接单位/负责人」而真源是「供应商/经手人」，且 9 页共 27 个操作入口是 `href="#"` 死链**；阻断级的数据矛盾有两处（单据详情 A-0024 的金额与供应商）。

## 六问速答

| # | 问题 | 结论 |
|---|---|---|
| 1 | 信息层级 | **基本成立**。页头三件套 + 右上主操作在 19 页成立。不成立 4 处：业务全流程图（有标题无图）、权限设置（有标题无矩阵）、库存（导出抢了主按钮）、盘点（看不出在盘哪个商品） |
| 2 | 排布逻辑 | **通过**。A 组页序为 页头/主操作 → 单据类型 chips → 筛选 → 表格 → 分页 → 说明，符合「先定位、再操作、再看数」；仅 chips 行挤在页头与筛选之间且 5 页重复 |
| 3 | 列与字段 | **最弱一环**。见 P1-1～P1-8：缺操作列、缺真源核心列、表头未右对齐、日期无年份、术语与真源冲突 |
| 4 | 一致性 | **不通过**。两套 CSS 世界（P0-1）+ 术语（P1-7）+ 状态色（P1-9）+ 三种日期格式（P1-8）+ 空态/分页只覆盖部分页（P1-10） |
| 5 | 状态覆盖 | **仅 1 页做全**。四态只在 `单据详情.html`；空态需手动加 `?state=empty`；无看价权限占位 0 处演示；禁用态只有登录页验证码 |
| 6 | 可用性硬伤 | **4 类**：26px 操作按钮（P1-12）、表格溢出被 `overflow:hidden` 裁掉且不能横滚（P1-13）、27 处死链（P0-3）、筛选与角色切换全无接线（P1-11）。hover 才可见的必要信息 **通过**（信息不依赖 hover） |

## P0 必须改（阻断使用）

- **[13 个列表页 / 共享层] 半数页面不加载共享层，各自内联一份旧 CSS 副本 → 亮暗、字号、空态、分页语义、排序、抽屉在这些页全失效**
  | 证据：`客户.html:8` 只有 `<link href="tokens.css">`+`fonts.css`，`客户.html:9` 起是内联 `<style>` 副本，没有 `page.css`/`ui.css`/`visual.css`/`polish.css`，也没有 `ui.js`；同构的共 13 页：客户、供应商、加工厂档案、商品资料、员工、权限设置、公司管理、盘点、库存流水、操作日志、API与集成、业务全流程图、冲正单据。对照 `采购单A.html` 加载 7 个 CSS + `ui.js`。后果：这 13 页没有 `.qd-dock`（无亮暗/字号切换）、无 `:focus-visible` 环（polish.css:27）、无空态、无表头排序、无 `#entry` 抽屉、筛选容器还叫 `.p-filters`（客户.html:40）而不是 `.toolbar`。
  | 改法：13 页删掉内联 `<style>` 副本，统一改为 `tokens → fonts → components → page → ui → visual → polish` 七件套 + `ui.js`；`.p-filters` 全量改名 `.toolbar`（page.css:17 已有该定义）。`单据详情.html`/`登录页.html` 是特殊壳，可保留独立布局，但需登记为「故意分叉」并复用 tokens/components。

- **[单据详情.html ↔ 采购单A.html] 同一单号 A-0024 出现三个金额、两个供应商**
  | 证据：`采购单A.html` 首行 `<td>A-0024</td><td>宏远五金</td><td>冷轧钢板 1.2mm</td><td class="num">12,000 千克</td><td class="num">¥86,400</td>`；`单据详情.html` 单据信息区写 `<dt>供应商</dt><dd>归档果业</dd>`、`<dt>金额合计</dt><dd class="money">¥13,600.00</dd>`，而同页明细 tfoot 是 `<span class="sum">¥27,880.00</span>`（13,600+10,440+3,840=27,880 自洽）。单头金额疑似抄了第一行金额。
  | 改法：详情页 `<dd class="money">` 绑定明细合计（27,880.00），供应商改回「宏远五金」，与列表页同一 mock 源；并让 12,000 千克 ¥86,400 的单价（¥7.2/kg）与商品资料「冷轧钢板 ¥7,200/吨」对上。

- **[9 个主数据/配置页] 唯一的操作入口是 `href="#"` 死链，且这些页没有 ui.js 拦截 → 点了只会滚到页顶**
  | 证据：`客户.html:98`、`供应商.html:98`、`商品资料.html:98`、`加工厂档案.html:98`、`员工.html:98`、`公司管理.html:98`、`盘点.html:98`、`权限设置.html:98`、`API与集成.html:98` 全部是 `<a href="#" class="btn" style="height:26px;padding:0 10px">编辑/审核/查看/吊销</a>`，共 27 处；`href="#"` 的拦截只写在 `ui.js:124` 的 `bindNav` 里，而这 9 页都没加载 ui.js。5 张单据页则走到另一个极端：表里干脆没有「操作」列，单号 `<td>A-0024</td>` 也不可点。
  | 改法：操作列指向真实地址（编辑抽屉 `data-drawer="#edit"` / 单据详情），5 张单据页首列单号改成链接 + 末列补「查看/打印」——真源 `SalesOrdersPage.tsx:1560` 单号就是 `<button onClick={() => setDetailId(order.id)}>`，`PurchaseOrdersPage.tsx:1044` 有 `<th>操作</th>`。

- **[业务全流程图.html] 页面名是流程图，内容是一张「还缺什么」的开发待办表**
  | 证据：`业务全流程图.html:97` `<thead><tr><th>单据</th><th>已经能做什么</th><th>还缺什么</th><th>页面</th></tr></thead>`，全页无节点、无连线、无方向；:100 note 写「按角色切换视角时，只保留该角色经手的节点，其余置灰」，但页面里没有任何可置灰的节点。`routes.ts` 第 19 页 page 字段是「业务全流程图」。

- **[权限设置.html] 核心职能「功能域 × 动作矩阵」在页面上根本不存在**
  | 证据：`权限设置.html:97` 表头只有 `<th>岗位</th><th>类型</th><th>权限摘要</th><th>状态</th><th>操作</th>`；:100 note 说「点「编辑」进矩阵：行＝功能域，列＝查看 / 新建 / 审批 / 导出；只读格子灰显」，而 :98 的「编辑」是 `href="#"` → 矩阵永远打不开。真源 `PermissionsPage.tsx`（18 KB）是有矩阵实现的。
